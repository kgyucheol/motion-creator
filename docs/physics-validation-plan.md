# 자세 정밀 편집과 물리 검증 설계 검토

검토일: 2026-09-08. 다중 부위 이동, 그룹 프리셋, F 카메라 포커스에 이어 아래의 회전·관절각 편집을 구현했습니다. 물리 검증은 설계 검토 단계이며 아직 구현하지 않았습니다. [Menagerie·MimicKit 검토](mimickit-review.md)도 참고하세요.

## 정밀 자세 편집: 11개 부위 핸들 + 회전 + 29개 관절각 패널

현재 화면의 11개 핸들은 관절 모터 자체가 아니라 공간상의 목표 지점입니다. G1의 29개 자유도는 이미 IK 계산에 모두 참여합니다. 핸들을 29개로 늘려도 새로운 자유도가 생기지는 않습니다.

구현한 편집 방식은 다음과 같습니다.

1. 손·발·골반에 회전 링을 제공합니다. 이동/회전 모드와 월드/로컬 축을 구분합니다. 여러 부위를 회전하면 그룹 중심에 대한 위치와 방향 목표를 함께 계산합니다.
2. 팔꿈치·무릎은 위치 드래그와 실제 관절축 회전 링을 제공합니다. 회전 링은 관절각 목표로 변환해 IK에 전달합니다. 손/발 끝을 고정하려면 해당 위치 고정을 명시합니다. 사용자 요청에 따라 별도 굽힘 방향 모드와 보조 목표 계산은 제거했습니다.
3. 펼쳐서 사용하는 29개 관절각 패널에서 슬라이더·숫자를 편집하고 적용합니다. 사람이 바꾼 관절각을 우선 목표로 두고 발 등 기존 고정을 유지하도록 IK를 다시 풉니다. 두 조건이 충돌하면 오차를 표시합니다.
4. 발은 위치와 방향을 고정하고, 손·골반 등은 위치만 고정합니다. 단일 손·골반은 고정 중에도 회전할 수 있습니다. 별도의 임의 방향 잠금 토글은 추가하지 않았습니다. 골반 회전은 루트 회전 변수를 활성화하며, 출력은 정규화된 quaternion과 최단 경로 보간을 사용합니다.

어깨/무릎/발목의 여러 회전축은 공간상 위치가 같거나 가깝습니다. 모두 동일한 위치 드래그 핸들로 표시하면 선택이 겹치고, 사용자가 바꾸려는 것이 위치인지 관절 각도인지 혼동되기 쉽습니다. 현재 작업 화면은 유지하고 정밀 조정을 단계적으로 노출하는 편이 적절합니다.

## 물리 검증의 의미

다음 세 질문은 서로 다릅니다.

- 이 자세에서 지면 반력과 모터 토크가 정적 평형을 만들 수 있는가?
- 특정 제어기가 이 자세를 중력 아래에서 일정 시간 유지할 수 있는가?
- 실제 사용할 제어기가 자세 사이의 이동과 박스 하중·외란까지 감당할 수 있는가?

정적 평형이 가능해도 PD 게인이 부적절하면 넘어질 수 있고, PD 시험에서 실패했다고 그 자세 자체가 물리적으로 불가능한 것은 아닙니다. 결과는 '정적 평형 검사', '지정 제어기 유지 시험', '참조 모션 추종 시험'으로 각각 기록해야 합니다.

현재 편집기는 `qpos`를 직접 설정하고 FK/IK를 계산합니다. 이때 발 고정은 편집 제약이며 물리 접착이나 실제 반력이 아닙니다. 검증용 시뮬레이션에서는 **루트의 6자유도를 모두 자유롭게 두고**, 발 접촉과 모터 토크로만 로봇을 지지해야 합니다. 루트를 고정하거나 매 프레임 참조 qpos를 덮어쓰는 재생으로 균형을 판정하면 안 됩니다.

## 1단계: 정적 균형·필요 토크 검사

CPU에서 빠르게 실행하는 첫 단계로 추천합니다.

- 유효한 발 접촉과 로봇/바닥·자가 충돌을 검사합니다.
- 로봇과 박스의 합성 무게중심, 지지 영역, 경계까지의 여유를 표시합니다. 무게중심 투영만으로 토크 한계나 파지 가능성을 판정하지 않습니다.
- 고정된 자세에서 관절 토크와 접촉력을 변수로 평형 문제를 풉니다.

MuJoCo의 운동 방정식은 `M(q) v_dot + c(q,v) = tau + J(q)^T f`입니다. 정적 검사에서는 속도와 가속도를 0으로 두고, 실제로 구동되는 29개 관절에만 토크를 허용합니다. 루트에 가상의 구동 힘/모멘트를 허용하지 않는 것이 핵심입니다. [MuJoCo 계산 문서](https://mujoco.readthedocs.io/en/stable/computation/index.html)

제안하는 최적화 변수는 29개 관절 토크와 양발의 접촉점별 힘입니다. 고정된 접촉 위치의 Jacobian과 중력항을 MuJoCo에서 얻고, 다음 조건을 만족하는 QP를 풉니다.

- 로봇 전체와 비구동 루트 6축의 힘/모멘트 평형
- 각 접촉점의 수직력은 0 이상
- 마찰 원뿔의 보수적 선형 근사
- 발 지지면 내 접촉점 배치에 따른 발목 모멘트 한계
- 관절별 허용 토크와 사용할 안전 여유

박스를 함께 고려할 때는 박스 무게중심과 파지점도 포함해 박스의 힘/모멘트 평형을 풀어야 합니다. 첫 구현은 '박스가 손에 확실히 고정되어 있다'는 가정 아래 하중에 따른 토크·균형만 평가할 수 있습니다. 이것을 파지 안정성 검증으로 표시해서는 안 됩니다.

현재 모델의 `actuatorfrcrange`를 초기 범위로 사용할 수는 있지만, 정격 연속 토크인지 순간 최대 토크인지 실제 하드웨어 자료와 대조해야 합니다. 장시간 유지 판정에는 연속 토크와 발열 제한이 필요합니다.

## 2단계: MuJoCo 자세 유지 시험

별도의 MuJoCo 모델/데이터 인스턴스에서 실행하여 편집 중인 자세와 키프레임을 바꾸지 않습니다.

- 중력, 바닥 접촉, 실제 마찰, 자유 루트 활성화
- 29개 모터에 토크 제한 적용
- 우선 PD + 정적 평형에서 구한 feed-forward 토크로 시험
- 가능하면 사용자의 기존 전신 제어기를 같은 인터페이스에 연결
- 예를 들어 5초 정지 유지 후, 크기와 방향을 명시한 작은 외란을 가하는 시험
- 루트 높이/기울기, 관절 추종 오차, 발 미끄럼, 토크 포화 비율, 접촉력 등을 기록

시간 간격·PD 게인·마찰을 조금 바꾼 여러 시험에서도 유지되는지 확인하면 단일 설정에만 맞는 결과를 구별할 수 있습니다. 시험 시간·외란 크기·통과 기준은 공장 작업 조건에 맞춰 정하며, 모델 오차까지 없애는 실제 하드웨어 보증은 아닙니다.

## 3단계: 기존 제어기로 참조 모션 추종

편집기에서 내보낸 모션을 컨트롤러의 입력 형식으로 바꾸고, 웅크리기·박스 들어 올리기·일어서기를 연속 재생합니다. 이후에 기존 로코모션 정책과의 전환을 검증합니다.

속도와 접촉 전환이 있는 전체 모션은 정적 검사만으로 판정할 수 없습니다. 이 단계에서 속도·가속도, 제어 지연, 양손과 박스의 관계, 실제 로코모션 전환 시점도 포함합니다.

## Isaac Sim/Isaac Lab에서는 어떻게 유지하는가?

Isaac Sim의 PhysX는 중력과 접촉을 계산합니다. Isaac Lab의 위치/속도 구동은 강성·감쇠를 쓰는 implicit drive 또는 명시적인 PD actuator 모델 등으로 관절 토크를 만듭니다. 휴머노이드 전체 균형을 유지하는 행동은 별도의 제어기 또는 학습 정책이 담당합니다. 시뮬레이터를 선택하는 것만으로 임의의 자세에 대한 균형 제어기가 자동으로 생기는 것은 아닙니다. [Isaac Lab actuators](https://isaac-sim.github.io/IsaacLab/main/source/overview/core-concepts/actuators.html)

따라서 이 컴퓨터에서는 먼저 MuJoCo의 단일 로봇 CPU 시뮬레이션으로 검사하고, 대규모 병렬 학습이 필요해질 때 Isaac Lab을 검토하는 구성을 추천합니다.

## MuJoCo 모델과 SONIC의 역할

MuJoCo의 물리 모델과 학습된 정책 모델을 구분해야 합니다.

- 물리 모델: G1의 질량·관성·관절·충돌체·모터 설정입니다. 이미 로컬 MJCF에 대부분 들어 있습니다. 공식 [MuJoCo Menagerie의 G1](https://github.com/google-deepmind/mujoco_menagerie/tree/main/unitree_g1) 모델과 대조할 수 있습니다.
- 통합 시뮬레이터: [Unitree 공식 unitree_mujoco](https://github.com/unitreerobotics/unitree_mujoco)는 Unitree SDK2 기반 제어 프로그램과 연결하는 시뮬레이션 구성을 제공합니다. 실제 사용하는 SDK/WBC 인터페이스를 재사용하려는 경우 관련이 큽니다.
- 학습 정책: [GEAR-SONIC / GR00T-WholeBodyControl](https://github.com/NVlabs/GR00T-WholeBodyControl)은 참조 모션을 추종하는 학습 제어기와 배포 코드를 제공합니다. 공식 저장소에 MuJoCo 시뮬레이션 경로도 있습니다. 정적 평형 검사의 필수 의존성은 아닙니다.

SONIC을 연결하면 '이 자세가 SONIC의 관측/참조 표현과 정책으로 유지되는가'를 시험하게 됩니다. 현재 NPZ를 그대로 넣는다고 동작하는 것은 아니며 관절 순서, 루트/heading 좌표계, 참조 표현·시간 구간, 관측 정규화, 게인 등을 맞추는 어댑터가 필요합니다. 사용자가 이미 가진 WBC/로코모션 정책이 최종 배포 대상이라면 그 정책을 우선 검증하는 편이 결과를 해석하기 쉽습니다.

## 현재 확보된 데이터와 추가로 필요한 데이터

로컬 G1 MJCF를 확인한 결과입니다. 실제 G1 제원으로 확정한 수치는 아닙니다.

- 모델 바디 질량 합: 약 35.112kg
- 자유 루트 + 모터 29개
- 기본 timestep: 0.002s, 중력: -9.81m/s²
- 기본 바닥 friction: [1.0, 0.005, 0.0001]
- 모터는 토크 입력이며 자동 자세 유지 PD는 포함되지 않음
- Unitree SDK의 `example/g1/low_level/g1_ankle_swing_example.cpp`에 예제 Kp/Kd가 있음. 실제 사용 정책의 게인과 같다고 가정하지 않음

다음 단계에서 필요한 자료는 다음과 같습니다. 현재 구현한 편집 기능에는 필요하지 않습니다.

| 자료 | 용도 |
|---|---|
| 실제 WBC/정책 코드 또는 ONNX/PT 파일 경로와 실행 설정 | 최종 배포할 제어기로 자세 유지·추종 시험 |
| 관절 이름/순서, 관측·행동 정의, 주기, Kp/Kd, 토크/속도 제한 | 컨트롤러와 MuJoCo 연결 |
| 실제 G1 옵션과 추가 장착물의 질량·위치 | 모델 관성/무게중심 보정 |
| 박스 무게 범위, 크기, 무게중심, 양손 파지 위치·방식 | 하중과 파지 가정 설정 |
| 발바닥/바닥 마찰 또는 보수적으로 사용할 범위 | 미끄럼·균형 여유 검사 |
| 기대 유지 시간과 허용 기울기·미끄럼·추종 오차 | 시험 통과 기준 설정 |

제어기 자료가 없어도 명시적인 가정으로 1단계 정적 검사를 만들 수 있습니다. 2–3단계의 결과를 실제 배포와 연결하려면 실제 제어기 설정이 필요합니다.
