# G1 그리퍼 모델과 라면용기 장면

상단 **로봇 모델** 선택에서 기본 손과 **G1 그리퍼(왼 주걱/오른 받침)**를 전환할 수 있다.
현재 모션은 브라우저에 모델별로 보관하고 전환 후 해당 모델의 초안을 복원한다.
전환은 같은 서버에 연결된 모든 탭에 영향을 준다. WBC 세션이나 물리 계산이
남아 있으면 먼저 종료해야 한다. 저장 파일로 남기려면 모션 저장을 사용한다.

기존 G1: `./run.sh --model g1`

G1 그리퍼: `./run.sh --model g1-tools --port 8766`

브라우저에서 http://127.0.0.1:8766 을 연다. 모델은 서버별로 독립적으로 선택한다.
로컬 자산 `assets/g1_scoop_endsupport/`가 필요하다. 공급된 URDF 전체를 컴파일하고
로봇 기준 왼손 주걱/오른손 받침으로 도구를 좌우 반사한다. 질량·관성·충돌체와
TCP도 함께 반영한다. 원본 자산은 수정하지 않는다.

왼손/오른손을 선택해 W(위치), E(회전)로 TCP를 조종한다. 기존 29관절 제어와
키프레임 저장/재생을 사용할 수 있다. 모델별 fingerprint가 다르므로 기존 더미손
프로젝트를 도구 프로젝트로 자동 변환하지 않는다. 새 모델에서 새 모션을 만든다.
기존 양손 박스 파지 맞춤/파지력 보상은 더미손 전용이므로 도구에서는 사용하지 않는다.

오브젝트 편집 아래의 **라면용기 4열 × 3층 + 열린 상자 생성**을 누른다.
열린 상자는 고정된 바닥/네 벽 5개, 용기 묶음은 동적 원기둥 12개로 구성된다.
원기둥 하나는 여러 용기가 겹쳐진 묶음 하나를 근사한다. 초기 지름 100mm,
길이 230mm, 묶음 질량 150g이며 생성 후 각 오브젝트의 크기·위치·질량을 편집한다.
원기둥 축은 로봇 전후 방향(X)이다. 상자 바닥 높이는 620mm이다.

물리 미리보기 및 WBC에서 실제 그리퍼 충돌체·질량·관성과 원기둥 접촉을 계산한다.
상자 벽의 고정은 월드 weld로 구현하며 용기는 고정하지 않는다.
학습된 G1 정책을 새 도구로 재학습한 것은 아니므로 도구 하중에서의 보행 및
용기 꺼내기 성공은 별도의 모션과 실험으로 평가해야 한다. 개별 컵의 테이퍼,
중첩/분리 마찰과 변형까지 재현하는 모델은 아니다.

## 라면 묶음 꺼내기 시퀀스

G1 그리퍼 모델에서는 오른쪽 패널의 **라면 꺼내기**를 사용할 수 있다.

1. 움직일 라면 묶음을 선택한다.
2. 패널에 표시된 물체 중심·충돌 지름이 맞는지 확인한다. 상자를 기울일 경우 그룹 변환을 먼저 완료한다.
3. 왼쪽 패널에서 원하는 자세를 만든 뒤 **현재 자세를 차렷자세로 저장**한다. 이 프리셋은
   로봇의 **기본 서기 자세**와 별도로 프로젝트에 저장된다.
4. 삽입 시작 높이, 인양 높이, 몸쪽 이동량·반복 횟수와 힘 상한을 설정한다.
5. **물체 위치로 7단계 시퀀스 생성**을 누른다.
6. 생성된 단계를 개별 확인한 뒤 **이 시퀀스 물리 실행**으로 검증한다.

UI의 생성 단계는 차렷자세 → 삽입 위치 탐색 → 양손 무충돌 접근 → 양손 지지 안정화 →
라면묶음 수직 인양 → 상자 밖으로 꺼내기 → 운반 자세 유지의 7단계다. 무충돌 접근은
물체 위 안전점으로 이동한 뒤 왼 주걱과 오른 받침을 한쪽씩 수직 삽입하는 세부 키프레임으로
구성된다. 이는 대상 물체 주변의 정해진 수직 통로를 사용하는 장면 상대 휴리스틱이며,
임의 장애물 전체를 탐색하는 범용 충돌 경로 계획기는 아니다.

`SceneObject.position`은 물체의 기하/충돌 중심이다. 가져온 GLB part는 해당 part bounds의
중점이고, 그룹을 기울이면 개별 물체의 중심과 quaternion도 월드 좌표로 함께 갱신된다.
planner는 이 중심과 충돌 지름을 사용해 양쪽 지지점을 만들며, 원기둥 장축 이외의 두 축 중
월드 위쪽에 가까운 축을 상자 위쪽 축으로 사용한다. 따라서 상자 그룹을 기울인 만큼 삽입·
인양 방향과 도구 자세도 함께 기울어진다. 삽입 시작점과 총 인양 거리는 대상 지름보다
작게 입력해도 최소 한 지름으로 자동 보정된다.

현재 편집기 TCP 방향은 도구 고유 장착 방향을 판별하는 기준으로만 사용한다. 도구의 현재
로컬 축 중 수직에 가장 가까운 축을 기울어진 상자 위쪽 축에 맞춘다. 마지막 운반자세에서는
이 축을 물체에서 로봇 몸통으로 향하는 방향으로 설정 각도만큼 점진적으로 꺾고, 전신 IK의
posture reference를 저장된 차렷자세(없으면 G1 기본 서기)로 두어 하체·허리가 시작 자세에
가까이 남도록 한다.

삽입 위치 탐색 단계의 입력 계약은 `scene_ground_truth`와 `rgb_pose_estimator`를 구분한다.
현재는 시뮬레이션 오브젝트의 월드 위치·회전을 사용해 양쪽 삽입점, 상부 접근점과 삽입축을
계산하고 키프레임 metadata에 저장한다. 추후 RGB 인식기는 같은 `object_pose_world`를 공급하면
나머지 경로 생성기를 그대로 사용할 수 있다. 그리퍼 URDF에는 `d435_link`가 `torso_link`에
`xyz=(0.0576235, 0.01753, 0.42987) m`, `rpy=(0, 0.8307767, 0) rad`로 고정되어 있다.
이는 roll 0°, pitch 약 47.6°, yaw 0°다. 다만 optical frame과 RGB 내부 파라미터는 URDF에
없으므로 실카메라 드라이버의 보정값이 추가로 필요하다.

편집기와 물리 재생 화면은 이 `d435_link` FK를 따라가는 **Head Cam PiP**를 표시한다. PiP는
URDF 링크의 +X를 시선 방향, +Z를 영상 위쪽으로 해석하고, 보정값이 없으므로 60° 임시 FOV를
사용한다. 편집 기즈모·관절 마커·고스트·콜리전 시각화는 PiP에서 숨긴다.

각 단계에는 양쪽 TCP 목표와 삽입축, 임피던스 파라미터가 저장된다. 키프레임 사이 경로는
관절각만 보간하지 않고 양쪽 TCP 위치·방향을 보간한 뒤 IK로 다시 계산한다. 물리 재생은
기본 PD 또는 GEAR-SONIC 토크 위에 500 Hz operational-space 임피던스 토크를 더한다.
삽입 중에는 삽입축 강성을 낮추고 횡방향과 도구 방향 강성을 높여, 상자 벽이나 주변 묶음과
접촉할 때도 가르친 자세로 돌아가면서 축 방향으로는 양보하도록 한다. 토크는 관절 한계의
설정 비율로 제한한다.

현재 힘 측정은 임피던스의 목표 힘을 폐루프로 맞추는 용도가 아니라 안전 감시다. 왼쪽 또는
오른쪽 도구와 어떤 장면 오브젝트 사이의 접촉력이 설정 상한을 10 ms 이상 연속 초과하면
물리 계산을 중단한다. 즉 물체 접촉으로 생긴 TCP 위치·방향 오차에는 능동 대응하지만,
힘 센서값을 이용해 일정한 접촉력을 유지하는 하이브리드 force/impedance controller는 아니다.
실로봇 적용 시에는 손목 F/T 센서 또는 관절 외란 토크 관측기와 실시간 토크 명령 계층을
추가하고, 비전 포즈는 저속 외부 참조 갱신에만 사용하는 것이 안전하다.

**Physics ON/OFF 전환 자체는 즉시 수행되며 시뮬레이션을 계산하지 않는다.** Physics ON에서
재생을 누르면 현재 키프레임부터 끝까지 MuJoCo를 500 Hz로 스텝하고, 그 결과를 저장한 뒤
재생한다. 이 선계산은 결과 탐색, 반복 재생, 물체 궤적 확인과 계산 중 UI 분리를 위한 현재
편집기 구조이다. MuJoCo 뷰어도 매 프레임 물리 스텝을 계산하지만 보통 실시간보다 빠르게
연속 계산하므로 별도 대기처럼 보이지 않는다. GEAR-SONIC을 함께 사용하면 50 Hz 정책 추론도
추가되므로 기본 PD보다 더 걸릴 수 있다.
