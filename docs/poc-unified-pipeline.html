Motion Strategy & Delivery Plan

Kimodo로 기준선을 만들고, ARDY는 같은 시험으로 승격한다

모션 생성 성공과 물리 실행 성공을 분리한다. 후보 모션은 관절·접촉·충돌 검사를 거쳐야 하며, 최종 판단은 GEAR-SONIC 추적 시뮬레이션의 측정값으로 한다.

STEP A · OFFLINE BASELINE

Kimodo 후보 라이브러리

텍스트 + root/end-effector/keyframe 제약으로 G1 모션을 여러 개 생성한다.

  • 웅크리기·pregrasp·lift·stand·place 기본 동작
  • 제약 오차·발 미끄럼·관절 범위로 1차 선별
  • 좋은 후보와 seed를 재현 가능한 asset으로 저장
→
STEP B · ONLINE CANDIDATE

ARDY Shadow / A·B Test

동일한 TaskSpec을 ARDY 조건으로 변환해 온라인 재계획 가능성을 비교한다.

  • G1 25 FPS, waypoint·full-body·손/발 제약
  • GPU/TensorRT에서 generation time < buffer 검증
  • 정밀 파지·중간 피드백 대응 품질 비교
→
STEP C · PHYSICAL GATE

GEAR-SONIC → Sim2Real

공통 MotionRef 어댑터를 통과한 후보만 WBC로 추적하고 단계별 성공을 판정한다.

  • MuJoCo 빠른 회귀 → Isaac 기반 상세 검증
  • 접촉·낙하·토크·추적 오차를 자동 기록
  • 속도·힘 제한을 둔 실기 1회 → 반복 데모
도구이번 PoC에서의 역할강점확인할 리스크 / 승격 조건판정
Kimodo오프라인 모션 후보 생성·기준 라이브러리G1 모델, 텍스트+다양한 기구학 제약, 다중 샘플, MuJoCo/ProtoMotions 연결생성 시간과 물리 실행 가능성은 별도. 핵심 동작별 sim 성공 후보 확보먼저 적용
ARDY온라인 보정·재계획 후보Kimodo 계열 제어성을 지향하며 autoregressive 생성, streaming prompt·waypoint 지원실시간성은 GPU/TRT 조건에서 측정. Task 제약 정밀도와 WBC 추적 성공률이 Kimodo 기준선 이상병행 평가
GEAR-SONIC모션 생성기가 아닌 전신 추적 제어기Unitree G1 reference tracking, 50 Hz, sim/real 배포 경로joint/좌표계/시간축 adapter, 제어권 handoff, 접촉 하중 하의 안정성고정 계층
M0 · 계약 고정TaskSpec · MotionRef · ExecutionReport · 좌표계Gate: replay 재현
M1 · 상자 1 cycle도착 자세부터 Kimodo → SONIC simGate: pick–place 성공
M2 · NAVI 통합staging pose·명령권 handoff·반복Gate: 5회 연속
M3 · 라면 variant원통 묶음 인지·저힘 파지·짧은 shiftGate: 손상 없이 반복
M4 · ARDY 승격동일 suite A/B·온라인 재계획·실기 제한시험Gate: latency+성공률

현재 확인: 로컬 ARDY→SONIC CPU 파이프라인은 실행되지만 기본 상자 후보는 접근 timeout/웅크리기 전도 이력이 있어 아직 팔레타이징 성공으로 볼 수 없다. SLAM/NAVI는 별도 진행 중.
