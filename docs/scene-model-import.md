# 외부 3D 모델 가져오기

모션 편집기의 **3D 모델 가져오기**는 `.blend`와 `.glb`를 지원한다. `.blend`를 선택하면 서버가 처음 한 번 GLB로 변환하고, 이후에는 파일 내용 해시를 키로 삼아 변환 결과를 재사용한다.

## BLEND와 GLB의 역할

- `.blend`는 메시 원본, 모디파이어, 재질, 작업용 메타데이터를 보존하는 **제작 원본**이다.
- 브라우저의 Three.js와 모션 편집기 런타임에는 `.glb`가 적합하다. 단일 바이너리 파일이고 로딩이 빠르며 Blender 설치 여부와 무관하게 다시 표시할 수 있다.
- 따라서 BLEND를 그대로 런타임 포맷으로 쓰는 이점은 없다. 사용자가 BLEND를 업로드할 수 있다는 편의는 유지하되, 실제 표시에는 GLB 변환이 필요하다.
- `.glb`를 직접 가져오면 메시 재변환 없이 등록한다. 외부 도구에서는 표준 glTF의 미터 단위·`+Y 위쪽` 설정과 적용된 오브젝트 스케일을 권장한다. 편집기가 이를 URDF의 `+Z 위쪽`으로 바꾼다.

## 좌표계 변환

모션 편집기와 G1 URDF는 오른손 좌표계의 `+X 전방, +Y 좌측, +Z 위쪽`을 사용한다. Blender도 `+Z 위쪽`이므로 BLEND 가져오기는 Blender 좌표와 미터 스케일을 그대로 유지한다. 따라서 열린 상자의 개방면이 Blender에서 `+Z`라면 편집기에서도 `+Z`를 향한다.

표준 glTF/GLB는 `+Y 위쪽`이므로 직접 가져올 때 다음 축 변환을 먼저 적용한다.

- GLB `+X` → 편집기 `+X`
- GLB `+Y` → 편집기 `+Z`
- GLB `+Z` → 편집기 `−Y`

축 변환 이후의 바운딩 박스로 표시 크기를 계산한다. 물리 충돌체는 모델 종류에 맞는 별도 단순 프록시를 저장할 수 있다. 예전에 가져온 GLB 프로젝트도 열 때 저장된 크기·축·충돌체 정보를 자동으로 갱신한다.

## 여러 오브젝트가 들어 있는 파일

GLB/BLEND에서 작성자가 나눈 루트 오브젝트 노드를 각각 독립적인 장면 오브젝트로 가져온다. 메시 안에서 서로 떨어진 면이나 솔리드는 추가로 분해하지 않는다. 따라서 `cardboard_box_72x55x40cm.glb`의 바닥과 네 벽은 상자 1개로 유지되고, `ramen_box_packing_4x3.glb`는 상자 1개와 라면용기 묶음 12개, 총 13개가 된다. 한 파일에서 가져온 구성요소는 자동으로 같은 오브젝트 그룹에 등록된다. 각 오브젝트는 원본 GLB 노드를 직접 사용하므로 내장 머티리얼과 텍스처도 유지된다.

뷰포트에서 장면 오브젝트를 선택하고 `Delete` 또는 `Backspace`를 누르면 해당 오브젝트를 삭제한다. 입력란에 커서가 있거나 로봇 부위를 선택한 상태에서는 삭제 키가 장면 오브젝트를 제거하지 않는다.

## 화면 메시와 물리 충돌체

가져온 정밀 메시는 화면 표시에 사용하고 MuJoCo는 안정적인 단순 충돌체를 사용한다.

- `cardboard_box_72x55x40cm.blend`: 열린 상자(바닥 + 네 벽) 충돌체, 기본 고정
- `ramen_container_scan.blend`: 가장 긴 축을 중심으로 하고 단면의 작은 치수를 지름으로 삼는 내접 원통 충돌체, 기본 1 kg 동적 물체
- 그 밖의 모델: 메시 정점에서 자동 계산한 convex hull 충돌체(최대 256 정점)

오브젝트 검사기에서 크기, 질량, 마찰, 고정 여부를 바꿀 수 있다. 화면 메시와 충돌체가 크게 다르면 물리 결과가 시각과 다를 수 있으므로 충돌체 크기를 함께 맞춰야 한다.
메인 편집기 뷰포트 상단의 `콜리전` 버튼을 누르면 원본 메시를 숨기고 실제 Physics/WBC 프록시만 와이어프레임으로 확인할 수 있다. 파지 키프레임 고스트는 물리 오브젝트가 아니므로 이 보기에서 제외된다.

## 상자와 내용물 함께 기울이기

상자와 라면용기를 각각 가져온 뒤 **OBJECT GROUPS**에서 두 개 이상의 물체를 선택해 그룹을 만든다. 그룹 중심 위치나 회전값을 바꾸면 모든 구성 물체의 위치와 방향이 하나의 강체 배치처럼 함께 변한다. 그룹은 편집 편의를 위한 부모 트랜스폼이며, 물리 재생을 시작하면 각 물체는 고정 여부와 질량에 따라 독립적으로 시뮬레이션된다.
