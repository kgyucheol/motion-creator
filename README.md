# G1 Motion Creator

29자유도 Unitree G1의 참조 모션을 만드는 로컬 편집기입니다. MuJoCo로 전신 IK를 계산하고 Three.js로 실제 G1 메시와 조작 축을 표시합니다. GPU 학습, Isaac Sim, 외부 서버는 필요하지 않습니다.

## 실행

이미 독립 Miniconda 환경과 빌드 결과가 준비되어 있습니다.

```bash
cd /home/kim/motioncreator
./run.sh
```

브라우저에서 **http://127.0.0.1:8765** 를 엽니다. 종료는 서버 터미널에서 `Ctrl+C`입니다. 포트가 사용 중이면 `./run.sh --port 8766`으로 실행할 수 있습니다. 정상 실행에는 Python 서버 하나만 필요하며 Node 개발 서버는 필요하지 않습니다.

같은 포트에서 G1 편집기가 이미 실행 중이면 `./run.sh`는 새 서버를 중복 실행하지 않고 기존 편집기의 주소를 안내합니다. 이때 브라우저에서 안내된 주소를 열면 됩니다.

환경을 직접 활성화하려면:

```bash
conda activate /home/kim/motioncreator/.conda
```

새로 설치할 때는 `./setup.sh`를 실행합니다. Python 3.11 환경, 잠긴 Python/npm 의존성, 프런트엔드 빌드를 설치합니다. 최초 설치에는 인터넷이 필요하고 이후 앱과 모델은 로컬에서 동작합니다. 시스템 ROS의 `PYTHONPATH`가 이 환경에 섞이지 않도록 `run.sh`와 테스트 스크립트가 경로를 분리합니다.

## 상자 태스크 · ARDY / SONIC CPU

상단 **상자 태스크**에서 실제/인식 상자 크기·6D pose·질량·마찰계수를 설정하고, **ARDY 모션 생성 → GEAR-SONIC CPU / MuJoCo 검증 → 결과 재생**을 실행할 수 있습니다. 태스크 설정과 참조 NPZ, 접촉력 로그, 검증 보고서는 `tasks/`에 저장됩니다. 상자를 손에 고정하지 않고 접촉·압착·마찰로 파지를 계산합니다.

CPU용 모델과 `.conda-policy` 환경은 설치되어 있습니다. 새 환경에서는 `./scripts/setup-task-cpu.sh`를 실행합니다. 이미 실행 중인 서버는 종료 후 다시 시작하고 브라우저를 새로고침해야 새 API/UI가 반영됩니다.

**모션 생성 완료와 물리 성공은 별개입니다.** 실제 후보 시험에서 접근 조건 시간 초과와 웅크리기 중 넘어짐을 확인했으며, 기본 팔레타이징 모션의 성공은 아직 확인되지 않았습니다. [사용법·물리 모델·저장 규약·API](docs/box-task-cpu.md)를 참고하세요.

## 편집 순서

**전체 관절 29** 탭에서 양 다리 각 6축, 허리 3축, 양팔 각 7축을 모두 직접 선택할 수 있습니다. 관절을 클릭하면 실제 관절축의 회전 모드로 전환됩니다. **E**로 회전 링을 드래그하거나 오른쪽 관절각 슬라이더·숫자를 수정한 뒤 **관절각 적용**을 누르세요. 관절 범위와 기존 손·발 고정 조건을 유지하며 IK를 계산합니다.

**W**는 선택한 관절 중심을 이동시키는 IK 목표입니다. 관절 자체의 회전은 E를 사용합니다. 같은 위치에 겹친 축은 **Alt+클릭**으로 차례로 선택하거나 왼쪽 목록에서 이름으로 선택하세요. **F** 포커스, Shift 다중 선택·함께 이동, 그룹 프리셋 저장은 새 관절에도 적용됩니다. 관절축 회전은 하나씩 선택하며, 여러 관절의 각도를 동시에 입력하려면 기존 29개 관절각 패널을 사용하세요.

**주요 부위 11** 탭은 기존 골반·손·발 등의 IK 핸들을 유지합니다. 새 관절의 자물쇠는 관절 중심의 공간상 위치를 고정하며 관절각 잠금은 아닙니다. 추가된 표시점은 선택·고정했을 때만 IK 위치 제약에 참여하므로 기본 자세 편집의 저항이 늘어나지 않습니다. 아래는 주요 부위 편집 순서입니다.

1. 골반·양 무릎·양발·양손·양 팔꿈치·양어깨 중 하나에 마우스를 올리거나 왼쪽 목록에서 선택합니다.
2. XYZ 축을 드래그합니다. 오른쪽 목표 좌표를 입력하고 **목표 위치 적용**을 누르거나, 축별 ± 버튼으로 1cm씩 이동할 수도 있습니다.
3. 기본적으로 양발의 위치와 방향이 고정되어 있습니다. 자물쇠로 각 부위를 고정/해제합니다. 손 등 다른 부위는 위치만 고정합니다. 고정된 부위를 직접 움직이려면 먼저 해제합니다.
4. **유연하게 따라오기**에서는 선택한 부위에서 관절 연결 경로가 먼 부위일수록 원래 위치에 더 남습니다. 저항을 높이면 이 성향이 강해집니다. **고정 부위만 유지**에서는 고정하지 않은 부위가 더 자유롭게 움직입니다.
5. 자세가 만들어지면 **자세 추가**로 새 키프레임을 만들거나 **선택 프레임에 반영**으로 기존 프레임을 수정합니다. 드래그한 자세는 자동으로 기존 키프레임을 덮어쓰지 않습니다.
6. 프레임을 선택해 이름, 이동 시간, 순서 등을 편집합니다. 이동 시간은 **이전 프레임에서 선택한 프레임에 도달하는 시간**입니다. 첫 프레임에는 이동 시간이 적용되지 않습니다. 멈춰 있는 구간은 같은 자세를 복제하고 시간을 지정합니다.
7. 재생 버튼으로 모션을 계산·재생하고 하단 슬라이더로 시간을 탐색합니다. 프리뷰는 최대 30fps이며 출력은 15–120fps 중 선택할 수 있습니다.
8. **저장 / NPZ**를 누르면 프로젝트 JSON, 참조 NPZ, 메타데이터 JSON이 `motions/`에 저장됩니다. 같은 이름도 타임스탬프와 식별자로 구분합니다. 오른쪽 저장 목록에서 다시 열거나 JSON 파일을 가져올 수 있습니다.

브라우저에는 편집 초안이 자동 저장됩니다. 파일 저장은 별도로 눌러야 합니다. 현재 편집 자세는 프로젝트의 `current_qpos`에 보존되지만 **NPZ는 타임라인에 등록한 키프레임만으로 생성**합니다. 자세 변경 후 반드시 키프레임에 반영하세요. 예제 불러오기는 현재 타임라인을 교체하므로 필요한 프로젝트는 먼저 저장하세요.

카메라: 빈 공간 왼쪽 드래그로 회전, 우클릭 드래그로 이동, 휠로 확대. 정면은 로봇 전방(+X)에서 바라봅니다. 황색 바닥 링은 로봇 무게중심의 바닥 투영 위치입니다.

## 다중 선택·그룹 프리셋·카메라 포커스

- 3D 핸들이나 왼쪽 목록을 클릭한 뒤 **Shift+클릭**으로 부위를 추가/해제합니다. 마지막 하나는 선택 상태로 남습니다. 일반 클릭은 단일 선택으로 돌아갑니다.
- 다중 선택 시 축이 선택 부위의 중심에 나타납니다. 축 드래그, 목표 좌표 입력, ±1cm 이동은 모든 선택 부위의 목표에 같은 이동량을 적용하고 전신 IK를 동시에 풉니다. IK 도달 오차 때문에 실제 부위 간 거리는 미세하게 달라질 수 있습니다. 오른쪽 오차는 선택 부위 중 최대값입니다.
- 선택한 부위 중 고정된 부위가 있으면 그룹 이동을 막습니다. 이동 전에 해당 자물쇠를 해제하세요. 다중 선택 중에는 마우스 호버가 선택 목록을 바꾸지 않습니다.
- **SELECTION GROUPS**에서 이름을 입력하고 새 프리셋으로 저장합니다. 프리셋 선택, 이름·부위 구성 수정, 삭제도 가능합니다. 기본 `양손` 프리셋을 제공합니다.
- 프리셋은 `presets/groups.json`에 저장됩니다. 브라우저를 바꾸거나 서버를 재시작해도 남으며, 다른 모션 프로젝트에서도 사용할 수 있습니다. 저장하는 것은 부위 조합입니다. 자세·고정 상태·관절각은 그룹 프리셋에 포함하지 않습니다.
- 부위를 선택하고 **F**를 누르면 해당 부위를 중심으로 카메라를 맞춥니다. 여러 부위면 모두 보이도록 중심과 거리를 맞춥니다. 텍스트나 숫자 입력 중에는 F 단축키가 동작하지 않습니다. 오른쪽 `선택 부위 보기 F` 버튼으로도 사용할 수 있습니다.
- 부위를 선택한 뒤 **W**는 이동, **E**는 회전 모드로 전환합니다. 회전은 손·발·골반, 단일 팔꿈치·무릎 및 전체 관절 29 탭의 모든 단일 관절에서 지원하며 기존 고정을 자동 해제하지 않습니다. 입력 중이거나 드래그·계산·재생 중에는 모드 전환을 막습니다.

## 회전·29개 관절각 정밀 편집

- **손·발·골반 → 회전**: 회전 링을 마우스로 드래그합니다. 월드/로컬 축을 선택할 수 있습니다. 숫자 입력은 월드 XYZ Euler 각도(도)이며, 축별 ±1° 버튼은 선택한 월드/로컬 축을 따릅니다. Euler 숫자는 같은 방향에서도 표현이 바뀔 수 있으므로 큰 회전은 링을 사용하세요.
- **양손 그룹 → 회전**: 그룹 중심을 기준으로 두 손의 위치와 방향을 함께 회전시킵니다. IK 도달 범위 내에서 목표를 추종합니다. 그룹에 고정된 부위가 있으면 먼저 고정을 해제합니다.
- **손 위치 고정 + 회전**: 단일 손은 위치를 유지하면서 손 방향만 바꿀 수 있습니다. 골반도 같습니다. 발은 위치와 방향을 함께 고정하므로 발을 회전하려면 고정을 해제해야 합니다.
- **팔꿈치·무릎 → W 이동 / E 회전**: 단일 선택 후 이동 축으로 위치를 옮기거나, 실제 관절축에 맞춘 링 하나로 굽힘 각도를 조정합니다. 숫자·±1° 조정도 지원합니다. 손/발 끝을 유지하려면 해당 부위를 고정하세요. 별도 굽힘 방향 모드와 보조 핸들은 제거했습니다.
- **29개 관절각 정밀 조정**: 패널을 펼쳐 슬라이더 또는 숫자로 각도(도)를 수정하고 **변경 각도 적용**을 누릅니다. 모델의 관절 범위 내에서 조정하며, 발 등 고정 조건을 함께 풉니다. 고정과 충돌하는 각도를 강제로 적용하지 않고 오차를 표시합니다.
- 회전한 자세도 키프레임에 반영한 뒤 **저장 / NPZ**로 저장합니다. 골반 방향은 quaternion 최단 경로로 보간하고, 손·발 방향과 공통 고정을 IK에 반영합니다. 기존 프로젝트도 계속 열 수 있습니다.

**월드 축**은 장면에 고정된 X/Y/Z 방향이고, **로컬 축**은 선택 부위의 현재 방향을 따라 회전하는 축입니다. 골반을 수직으로 내릴 때는 월드 Z, 기울어진 손 자체의 축으로 조정할 때는 로컬 축이 편리합니다. 그룹의 로컬 축은 기준으로 선택된 부위의 방향을 사용합니다. 이 선택은 드래그 축과 ±1° 버튼에 적용됩니다. 팔꿈치·무릎과 29개 개별 관절의 회전은 실제 관절축만 사용하므로 월드/로컬 전환을 비활성화합니다. 위치 숫자·±1cm 버튼과 Euler 숫자 입력은 월드 기준입니다.

편집 중 표시되는 COM/지면 정보는 기구학 참고값입니다. 동적 실행은 별도의 [상자 태스크 / SONIC CPU 검증](docs/box-task-cpu.md)에서 확인합니다. [초기 물리 검증 설계](docs/physics-validation-plan.md)도 참고하세요.

## 웅크리기 예제와 배치 생성

**웅크리기 예제 불러오기**는 서기 → 골반 약 16cm 하강 → 서기의 4초 모션을 만듭니다. 양발은 고정되고 손은 가까운 높이를 유지합니다. 완료된 예제 파일도 `motions/`에 있습니다.

```bash
cd /home/kim/motioncreator
PYTHONPATH="$PWD" OPENBLAS_NUM_THREADS=1 .conda/bin/python -m motioncreator.cli demo --depth 0.16 --fps 30
PYTHONPATH="$PWD" OPENBLAS_NUM_THREADS=1 .conda/bin/python -m motioncreator.cli export motions/프로젝트.json --fps 50
```

자동 생성기에서도 `Robot.solve()`로 목표 위치를 지정하고, 키프레임을 모아 `save_bundle()`을 호출할 수 있습니다. 모델이 허용하지 않는 웅크리기 깊이는 목표 오차로 반환됩니다. 이 예제는 양발 접촉을 유지하는 웅크리기 예제이며 박스 파지나 운반 로코모션까지 자동으로 생성하지는 않습니다.

## 출력 형식

**ProtoMotions 연결:** 기본 JSON·NPZ는 유지합니다. 저장 영역에서 **저장 시 ProtoMotions .motion / .pt 추가**를 선택하면 공식 G1 모델로 변환한 파일과 변환 보고서를 함께 저장합니다. 변환용 독립 Miniconda 환경도 준비했습니다. [사용 방법과 sim2sim 규약](docs/protomotions-integration.md)을 참고하세요. BVH를 거치지 않고 29개 관절을 이름으로 대응하고 대상 모델의 FK를 다시 계산합니다.

프로젝트 형식 식별자는 `motioncreator.g1.v1`입니다. 좌표계는 **오른손 좌표계, +X 전방, +Y 왼쪽, +Z 위**, 단위는 **m / rad / s**입니다. NPZ는 `numpy.load(path, allow_pickle=False)`로 읽을 수 있습니다.

| 필드 | 형상 | 의미 |
|---|---|---|
| `time` | N | 시작부터의 시간, 초 |
| `qpos` | N × 36 | 루트 xyz, 루트 quaternion wxyz, 29개 관절각 |
| `qvel` | N × 35 | MuJoCo 일반화 속도: 루트 선속도 3, 각속도 3, 관절속도 29 |
| `qacc` | N × 35 | 샘플 속도의 유한차분 가속도 |
| `root_pos` | N × 3 | 루트의 월드 위치 |
| `root_quat_wxyz` | N × 4 | 루트의 월드 방향 |
| `fps` | scalar | 참조 샘플링 주파수. 제어기 주기와 별개 |
| `root_lin_vel_world`, `root_ang_vel_world` | N × 3 | 월드 기준 루트 선속도·각속도 |
| `body_lin_vel_world`, `body_ang_vel_world` | N × B × 3 | 월드 기준 링크 원점의 선속도·각속도 |
| `body_parent_indices` | B | 저장 링크 순서 기준 부모 인덱스, 루트 -1 |
| `dof_pos`, `dof_vel` | N × 29 | 관절각과 관절속도 |
| `joint_names` | 29 | 실제 열 순서. 컨트롤러 순서에 맞춰 이름으로 매핑 필요 |
| `handle_pos` | N × H × 3 | 편집 부위·관절 중심의 월드 위치 |
| `handle_quat_wxyz` | N × H × 4 | 해당 링크의 월드 방향 |
| `handle_names` | H | 편집 핸들 순서. 기존 파일 H=11, 새 파일 H=40 (11부위 + 29관절) |
| `body_pos`, `body_quat_wxyz` | N × B × 3/4 | 월드 바디를 제외한 모델 링크 자세 |
| `body_names` | B | 링크 순서 |
| `contacts` | N × 2 | 왼발/오른발의 사용자가 지정한 지지 상태 |
| `com` | N × 3 | 로봇 자체 무게중심의 월드 위치 |
| `metadata_json` | 스칼라 문자열 | 모델 해시, 단위, 관절 순서, 검증 지표 |

내보내는 모든 quaternion은 **wxyz**입니다. 브라우저 표시 API의 quaternion은 Three.js에 맞춘 **xyzw**이므로 두 형식을 구분하세요. `qvel`의 루트 선속도는 월드 좌표, 루트 각속도는 MuJoCo 자유 관절의 로컬 좌표입니다. 관절 속도는 보간된 실제 qpos를 `mj_differentiatePos`로 차분하여 계산합니다.

`contacts`는 접촉력 센서나 물리 시뮬레이션 결과가 아닙니다. 구간 양끝에서 공통으로 고정된 발을 지지 상태로 기록합니다. 양끝에서 고정된 부위의 위치가 바뀌면 내보내기를 거부합니다. 발을 옮기는 구간은 끝점 중 하나에서 그 발의 고정을 해제하고 중간 자세를 추가하세요.

## 계산 방식과 범위

- 원본 모델: `/home/kim/unitree_ros/robots/g1_description/g1_29dof.xml`. 사용 메시와 모델을 `assets/g1/`에 복사했습니다. 원본 저장소는 수정하지 않았고 라이선스를 함께 보존했습니다.
- 관절 29개 + 루트 평행이동 3개를 푸는 유계 비선형 최소제곱 IK입니다. 골반 회전 목표를 지정하면 루트 회전 3개도 함께 풉니다. 다른 편집에서는 현재 루트 방향을 유지합니다.
- 선택 부위 목표, 고정 부위, 거리별 저항, 약한 관절 자세 유지 항을 함께 풉니다. 관절 범위는 모델에서 읽습니다. 발바닥 코너에는 바닥 관통 페널티가 있습니다.
- 고정은 수치 최적화이므로 수학적으로 완전한 고정은 아닙니다. 위치 오차 3mm 또는 발 방향 오차 0.015rad를 넘는 드래그 결과는 거부합니다. 목표·고정 오차를 UI에 표시합니다.
- 키프레임 사이에는 5차 시간 보간, 루트 quaternion 최단 경로 보간, 공통 고정 부위와 말단 방향의 IK 투영을 사용합니다. 매 프레임 보간 관절 자세를 기준으로 삼아 관절 해가 갑자기 바뀌는 현상을 억제합니다.
- 박스는 크기와 위치를 지정하는 시각 가이드입니다. 손가락/그리퍼, 파지 구속, 박스 운반 부착, 충돌 회피, 지지 다각형/균형 최적화, 토크·접촉력·하중·속도 한계 검증은 이번 범위에 포함되지 않습니다.
- **실제 로봇에 명령을 전송하지 않습니다.** 이 출력은 전신 제어기 입력으로 변환할 참조 데이터입니다. 기존 WBC/정책의 관절 순서, 정규화, 속도 및 접촉 규약에 맞춘 어댑터와 제어기에서의 실행 검증은 별도 단계입니다.

## 유사 프로젝트 및 연구

2026-09-08에 공식 자료를 확인했습니다.

- [Mink](https://github.com/kevinzakka/mink): MuJoCo 기반 미분 IK 라이브러리이며 G1 예제를 제공합니다. 위치·속도 제한과 충돌 회피 등 로봇 제약을 다루므로 이 편집기의 IK를 확장할 때 특히 관련이 큽니다. 완성된 키프레임 편집기는 아닙니다.
- [Disney RobotKeyframing](https://studios.disneyresearch.com/2024/11/04/robotkeyframing-learning-locomotion-with-high-level-objectives/): 정해진 시점의 목표를 키프레임으로 지정하고 학습 기반 로코모션에 반영하는 연구입니다. 자연어보다 지정한 시공간 목표를 사용하려는 방향과 가깝습니다. 이 G1 편집기에 바로 연결되는 도구로 확인한 것은 아닙니다.
- [Disney Factorized Motion Diffusion](https://studios.disneyresearch.com/2024/11/21/factorized-motion-diffusion-for-precise-and-character-agnostic-motion-inbetweening/): 드문 자세 제약을 만족하면서 중간 모션을 생성하는 연구입니다. 사람이 키프레임을 지정하고 사이를 자동으로 채우는 다음 단계와 관련이 있습니다. G1 물리 실행 가능성을 보장하는 패키지는 아닙니다.
- [Disney Robot Motion Diffusion Model](https://la.disneyresearch.com/publication/robot-motion-diffusion-model-motion-generation-for-robotic-characters/): 생성 모션과 로봇의 물리적 제어 가능성을 연결하는 연구입니다. 참조를 만드는 것과 실제 로봇에서 추종 가능한 모션으로 만드는 것의 차이를 다룹니다.

이번 구현은 학습 모델이나 자연어 생성을 사용하지 않고, **사용자가 지정한 부위 목표 + IK + 키프레임**으로 모션을 작성합니다. 위 자료의 완성 UI나 학습 가중치를 가져온 구현은 아닙니다.
